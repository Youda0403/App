# 구현 현황

설계서의 1차 범위를 기준으로 한 현재 상태다.
"실제 기기에서 확인했다"는 표현은 쓰지 않는다. 아직 에뮬레이터·자동화 테스트·빌드
검사까지만 마쳤기 때문이다.

## 구현한 것

### 오버레이
- `TYPE_APPLICATION_OVERLAY` 창을 **캐릭터마다 하나씩** 띄운다.
- `FLAG_NOT_FOCUSABLE` 로 키보드 포커스와 뒤로 가기를 가져가지 않는다.
- 한 명 표시 / 두 명 표시 전환.
- 각각 끌기, 함께 끌기.
- 크기(40~250%), 불투명도(20~100%) 조절. 오버레이를 껐다 켜지 않아도 즉시 반영.
- 캐릭터 길게 누르기로 즉시 숨김. 5분 / 30분 숨김. 상시 알림에서 숨기기·중지.
- 화면 밖으로 나가지 않도록 위치를 가둔다. 위치는 저장되고 되돌릴 수 있다.
- 포그라운드 서비스 유형 `specialUse` 선언 및 사유 기재 (Android 14+ 필수).

### 캐릭터 등록
- 사진 선택기로 이미지 등록. 별도 저장소 권한을 요구하지 않는다.
- 가장자리 투명 여백 자동 제거. 원본 사본은 따로 보관한다.
- 큰 이미지는 긴 변 1024px 기준으로 줄여 저장한다.
- 이름, 표시 높이, 바닥 기준점(가로·세로), 좌우 반전 편집.
- 원본 비율 유지. 가로 크기는 비율에 맞춰 자동 결정.
- 등록된 캐릭터가 없으면 기본 캐릭터 두 명을 자동 생성.
- 여러 캐릭터를 저장하고 표시할 두 명을 고를 수 있다.

### 기본 애니메이션
한 장으로 표현 가능한 동작만 넣었다.
숨쉬기, 미세 회전, 점프, 좌우 이동, 다가가기, 바라보기, 졸기, 리듬 타기, 놀라기,
벽에 부딪히기, 벽에 기대기, 쓰다듬김.

가로 이동과 점프는 창 안이 아니라 **창 자체를 옮겨** 처리한다. 창 안에서 움직이면
작은 창 밖으로 나갈 수 없기 때문이다.

동작이 바뀔 때는 직전 자세에서 새 자세로 약 0.26초에 걸쳐 건너간다. 그러지 않으면
동작이 바뀌는 순간 자세가 뚝 끊겨 보인다.

모든 동작의 변형 한계를 `PoseBounds` 에 못박아 두고, 창 여백을 그 값으로 계산한다.
단위 테스트가 실제 그리기와 같은 계산으로 네 모서리를 돌려 보며 창 밖으로 나가는지
확인한다. 여백은 그대로 다른 앱의 터치를 가로채는 면적이므로 필요한 만큼만 잡는다.

### 상호작용
- 톡 치면 놀라며 하트가 올라온다. 짝이 있으면 그쪽을 쳐다본다.
- **머리 위 기분 말풍선**: 하트·놀람·졸림·물음표·음표·머쓱함·못마땅함·말줄임표.
  이미지 한 장으로는 표정을 바꿀 수 없으니, 지금 무슨 기분인지 이걸로 알린다.
  둘이 무엇을 주고받았는지 알아볼 수 있게 하는 장치다. 설정에서 끌 수 있다.
- 한 명을 끌어다 다른 한 명 옆에 놓으면 관계에 맞는 '마주쳤을 때' 장면이 나온다.
- 둘이 겹치지 않게 서로 밀어내고, 새로 닿는 순간에는 콩 부딪힌다.
- **활발함 설정**: 이동 거리, 동작 속도, 상황극 빈도를 한 번에 조절한다.
  활동성 수치가 높은 캐릭터는 눈에 띄게 빠릿하게 움직인다.
- 걸을 때 좌우뿐 아니라 위아래로도 조금씩 자리를 옮긴다.
- 캐릭터 위를 좌우로 문지르면 쓰다듬기로 인식해 몸을 흔들고 하트가 계속 올라온다.
  (옮기려는 동작과 구분하기 위해, 손가락이 처음 자리에서 크게 벗어나지 않은 경우에만)
- 걷다가 화면 끝에 막히면 부딪히는 연출을 하고 돌아선다.
- 화면 끝에 있을 때는 가끔 기대어 쉰다.

표시는 설정에서 끌 수 있다.

하트·음표 같은 표시는 **터치를 받지 않는 별도 창**에 그린다. 캐릭터 창에 여백으로
자리를 만들면 그만큼 다른 앱의 터치를 가로채기 때문이다. 그 창은 불투명도를
0.8 로 고정하는데, Android 12 부터 이 값을 넘으면 창을 통과하는 터치가 막히기 때문이다.

### 크기 맞추기
두 캐릭터를 실제 오버레이 비율 그대로 발밑을 맞춰 나란히 보여 주고,
작은 쪽·큰 쪽·가운데 중 하나로 한 번에 키를 맞추거나 각각 조절할 수 있다.

### 음악 반응
- 활성 미디어 세션의 재생/일시정지 상태를 보고 동작을 바꾼다.
- 재생이 시작되면 바로 리듬을 타고 음표가 올라온다. 멈출 때는 하던 동작을 중간에
  끊지 않고 끝까지 마친 뒤 자연스럽게 평소 동작으로 돌아간다.
- 알림 접근 권한이 꺼져 있으면 `getActiveSessions()` 를 호출하지 않고 기능을 꺼진
  상태로 표시한다. 권한을 거절해도 오버레이는 정상 동작한다.

### 데이터
- Room 스키마에 2차 기능용 필드(관계, 방향, 성격 수치, 금지 행동, 행동별 이미지
  슬롯, 장면)를 **미리 넣어 두었다.** 2차에서 마이그레이션 없이 확장할 수 있다.
- 파괴적 마이그레이션을 쓰지 않는다. 업데이트해도 캐릭터와 설정이 유지된다.

## 아직 구현하지 않은 것 (2차)

앱 화면에서 "다음 버전"으로 표시해 두었다.

- 관계 엔진 (연인·친구·짝사랑·라이벌·가족·동료·사용자 정의)
- 상황극 스케줄러 (행동 조건·쿨다운·우선순위·중단/복귀)
- 장면 편집기
- 홈 화면 위젯
- 행동별 이미지 슬롯 활용 (앉기·잠들기·춤추기 등)
- 테스트 편의 기능 (이벤트 강제 실행, 장면 미리보기, 백업·복원)

## 차기 버전으로 분리한 것 (설계서 3절)

- 타자 입력 반응: 일반 오버레이는 다른 앱의 키 입력을 읽을 수 없다. 자체 키보드(IME)를
  따로 만들어야 하고, 한국어 조합과 개인정보 안내를 별도로 검증해야 한다.
- 음악 비트 동기화: 다른 앱의 오디오 캡처는 재생 앱이 허용해야만 가능하다.
  대부분의 음악 앱이 막아 두었다.

## 안드로이드가 막고 있어 해 줄 수 없는 것

이건 구현이 덜 된 게 아니라 **플랫폼 제약**이다.

| 항목 | 내용 |
| --- | --- |
| 민감 화면 자동 회피 | 일반 오버레이 앱은 지금 화면이 비밀번호 입력 화면인지 **알 수 없다.** 그래서 길게 눌러 숨기기, 알림 버튼, 일정 시간 숨김으로 사용자가 직접 치우게 했다. |
| 다른 앱이 캐릭터를 숨김 | Android 12+ 앱은 `setHideOverlayWindows()` 로 화면 위 오버레이를 강제로 숨길 수 있다. 은행 앱 등에서 캐릭터가 사라지는 것은 정상이다. |
| 키보드·시스템 화면 | 오버레이 표시가 제한될 수 있다. |
| 부팅 후 자동 시작 | Android 15 부터 `specialUse` 서비스는 부팅 직후 자동 시작이 제한된다. 재부팅 후에는 앱을 열어 직접 시작해야 한다. |
| 상시 알림 | 포그라운드 서비스는 알림을 띄워야 한다. 끌 수 없다. Android 13+ 에서 알림 권한을 거절하면 알림이 안 보이고, 알림에서 중지하는 기능도 쓸 수 없다(앱에서는 중지 가능). |
